## API (`src/worker/finisher.ts`)

Every route runs `requireUser` first (see auth below). Writes also pass `guardWrites`. Every response is `private, no-store`. Errors are `{ error, fields? }` with the same safe codes as before.

| Method and path | Purpose | Change from Next.js |
| --- | --- | --- |
| `GET /api/finisher/basics` | `today` and project options (Add task, New project) | new (was a Server Component call) |
| `GET /api/finisher/today` | Today view model (FIN-031) | new |
| `GET /api/finisher/tasks?project=` | Tasks tab (FIN-022) | new |
| `GET /api/finisher/task-groups/:group?project&offset` | Load more tasks; `offset` is a multiple of 50 up to 10,000 | was `GET /tasks?group=…` |
| `GET /api/finisher/tasks/:id` | Task page; 404 for missing or another user's | new |
| `GET /api/finisher/projects` | Projects tab (FIN-033) | new |
| `GET /api/finisher/projects/:id` | Project page (FIN-024); 404 for missing or another user's | new |
| `GET /api/finisher/closed?type&outcome&cursor` | Closed tab and Load more (FIN-032) | now returns the full tab data; Load more uses `page` |
| `POST /tasks`, `PATCH`/`DELETE /tasks/:id`, `POST /tasks/:id/actions` | Task writes | unchanged |
| `POST /projects`, `PATCH`/`DELETE /projects/:id`, `POST /projects/:id/actions`, `POST /projects/:id/slots` | Project writes | unchanged |
| `PATCH`/`DELETE /slots/:id`, `PUT /sessions` | Slots and session marks | unchanged |

- **Zod** validates `:id` (UUID, otherwise 404 without a database call), `:group` (enum, otherwise 400) and query strings (bounded lengths, offset rules, otherwise 400).
- **Bodies** still go through the domain parsers in `features/finisher/domain/validation.ts`. The forms use the same parsers, so client and server errors match. The 32 KB limit and object-only bodies are unchanged.

## Auth as built (AUTH-001 to AUTH-010)

- Sign-in runs in the browser (`src/features/auth/api.ts`) with the same error mapping the old routes had. The details are in [architecture](../architecture/auth.md#flows-and-routes).
- `/auth/confirm` and `/auth/callback` are SPA routes whose loaders exchange the token or code once, then `location.replace` the URL. The email templates are unchanged.
- The API reads `Authorization: Bearer`, verifies it with `getClaims(token)`, and requires `role = authenticated` and not anonymous. It queries Supabase with the publishable key plus that token.
- Route guards (`requireSession`, `redirectIfSignedIn`) reproduce the old proxy redirects, including `next` and `reason=expired`.
- On an API 401, the app signs out locally and opens `/sign-in?reason=expired&next=…`.
- After sign-in or sign-out, `navigateTo` does a full page load, so no state from the previous session survives in memory. On `SIGNED_OUT` from another tab, the query cache is cleared and the guards re-run.

## Behaviour changes worth knowing (all deliberate)

- **Timezone.** Sent as the `X-Time-Zone` header on every API call. It replaces the `ph-tz` cookie and the `TimeZoneSync` component. An unknown or missing zone gives UTC, as before.
- **No `Origin` header.** A write without one is now accepted, because the Bearer token is the credential and CSRF does not apply. A foreign `Origin` is still refused (403).
- **`aria-current`.** `src/components/link.tsx` marks a link current only on its exact path (query ignored), so "Back to Projects" on a project page is not announced as the current page. The sidebar uses prefix matching for whole apps. The Closed-tab filter links now use `aria-current="page"` (was `"true"`), and the styling changed to match.
- **Not found.** A missing or foreign task or project shows an in-shell "Task/Project not found" page with a link back (FIN-017 still can't tell the two apart). Unknown URLs show a generic not-found page.
- **Document titles.** These come from each route's `staticData.title`. They stay generic for task and project pages.
- **Back/forward cache.** App HTML is served `no-store`, and a page restored from the back/forward cache without a session reloads. Together these keep Back-after-sign-out from showing personal content (architecture T9).
- **Theme bootstrap.** Moved from an inline script to `/theme-init.js`, so the CSP needs no `unsafe-inline` for scripts. This closes the CSP follow-up in auth.md and finisher.md.

## Not verified

- **Any signed-in screen in a browser.** There's no real or mock Supabase session in this run: no shell, Finisher views, mutations, optimistic updates, focus movement or toasts. The earlier Next.js run against a mock Supabase ([finisher.md](finisher.md)) covered them, but the SPA wiring (loaders, query invalidation, `useSuspenseQuery`, error and pending components, the 401 handler) is verified by type-checking only.
- **Phone width.** Headless Edge on Windows wouldn't render a 390px viewport, so mobile layout and the drawer weren't checked. The layout CSS is unchanged apart from the `#root` wrapper.
- **Real Supabase.** No sign-in flow, `getClaims` against real JWKS, PKCE exchange or email link was run (same list as auth.md "Not verified").
- **Deployment.** Nothing was deployed. `wrangler deploy`, the production `_headers` behaviour and Workers free-plan limits weren't exercised.

## Local setup

1. Node ≥ 22.12 (24 LTS recommended), then `npm ci`.
2. `.env.local`: `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (see `.env.example`). `.dev.vars`: `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` (see `.dev.vars.example`). These are the same browser-safe values. (On this machine, both files were generated from the existing `.env`, which still holds the old `NEXT_PUBLIC_*` names and is no longer read.)
3. Supabase dashboard: add `http://localhost:3000/**` and `http://localhost:4173/**` to the redirect URLs, and the same origins to the Google OAuth client's JavaScript origins. The rest of the checklist is in [architecture](../architecture/auth.md#configuration).
4. Run `npm run dev` and open http://localhost:3000. For the production build in workerd, run `npm run preview` (port 4173).

## Deploying (not done; needs your authorization)

1. `npx wrangler login`.
2. `npx wrangler secret put SUPABASE_URL` and `npx wrangler secret put SUPABASE_PUBLISHABLE_KEY`.
3. Make sure `.env.local` (or CI env) has the `VITE_*` values. They are baked in at build time.
4. `npm run deploy`. The site is served at `https://person-hub.<account-subdomain>.workers.dev`, or attach a custom domain.
5. Add that origin to the Supabase Site URL and redirect URLs, and to the Google JavaScript origins.
6. Rollback: `npx wrangler rollback`.

## Debt and follow-ups

- **Tokens in `localStorage`** (ADR-0003, architecture R6). An accepted risk with a strict CSP. Revisit if third-party scripts or more sensitive data arrive.
- **Bundle size.** The client is about 300 kB gzip in one chunk. Options: route-level code splitting (`lazy` route components), `zod/mini` for search schemas, and checking that `lucide-react` tree-shakes. Measure on a phone first.
- **No per-user write rate limit** (carried over from finisher.md). Options: a Postgres-side counter, or a Cloudflare rate-limiting rule (check what the current free plan includes).
- **No committed browser tests.** Add Playwright flows for the signed-in screens, using a test Supabase project or a mock Auth/API, with authenticated state kept out of Git.
- **`/auth/confirm` and `/auth/callback` loaders** aren't unit-tested. The mapping functions they call are. A router-level test would need a DOM environment.
- **Database types** are still hand-written (`supabase gen types` not run).
